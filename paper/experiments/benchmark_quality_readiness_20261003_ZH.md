# 非 ResearchRubrics benchmark：质量优化与工程准备

日期：2026-10-03。状态：**静态实现准备，未启动真实实验，尚无已证实的提分结果**。本轮按用户要求暂停实验，优先修正会损害答案质量的提示与实现细节；不承诺达到最优、SOTA 或优于基线。

## 适用协议与范围

|---|---:|---:|---:|---|

## 固定公开输入的质量策略

本轮准备的是基于公开文本任务的通用质量策略。规划和执行可以读取公开题面、显式约束、允许的公开证据、合法源经验和实际预算；私有答案、checklist、rubric、instruction IDs/kwargs、blocked-source 记录及 TEST 反馈不进入 actor 上下文。

策略应在真实运行前随代码、prompt、配置和工具边界冻结。Initial 与 Selected 使用同一执行质量策略，二者的差异仍是经验状态。跨 benchmark 迁移保留完整来源状态，不在目标上重新调参、挑 checkpoint 或增删经验。

| 工作类型 | 规划与交付要求 | 避免的质量损失 |
|---|---|---|
| 完整答案集合 | 从公开问题列出资格条件、范围与时间边界；保留每个符合条件的实体、必要限定、支持依据和规范名称；去重并检查排除条件 | 不以代表例子替代公开要求的完整集合，不通过猜测条目扩大答案 |
| 写作产物 | 明确类型、受众、口吻、语言、长度、视角、结构和必需内容；交付成稿；审查叙事或论证的一致性、具体性与重复 | 不把写作题改成创作建议，不为叙事作品强塞研究报告格式；虚构内容遵守公开任务设定 |
| 指令遵循 | 将公开格式、词数、句数、段数、关键字次数、大小写、语言和禁用内容转成执行检查清单；冲突按公开指令处理 | 不在正文前后添加未要求的解释、免责声明、Markdown 包装或检查记录 |
| 深度研究 | 建立公开需求与报告段落的覆盖关系；使事实、出处、数值、分析链、对比和建议互相对应；区分证据与推断 | 不以空标题、通用建议或没有支持的量化指标替代实际分析，不伪造引用或来源访问 |

约束清单仅从公开题面产生。模型预测的要求是辅助，不得覆盖显式指令，也不得把猜测数量当成必需答案数量。公开输入不足时准确说明缺口，并完成有支持的部分；不假称进行了外部检索或独立验证。

### 预算与交接保真

- 规划读取实际剩余 token、单次输出上限与执行时间，按公开要求的数量、长度和复杂度分配工作，为最终成稿、必要检查和完整协议响应保留空间。预计调用成本与真实账单分别记录。
- 不因希望提分而临时增加统一预算、放宽停止条件或忽略超时。角色、并发、单次输出和任务 token/时间边界仍由正式冻结配置决定；不额外引入固定任务调用次数上限。
- 对集合任务，完整条目清单及其资格证据是实质内容；压缩首先删除重复，不将实际集合替换成几个例子。Contributor 与 Writer 的长度要求分开，最终产物不继承 contributor 摘要上限。
- 对多轮执行，已发布且仍有效的事实、计算和条目在后续账本中保留；修订能明确更正旧结论，不因一次精简响应静默丢失先前内容。Writer 读取可审计的累计交接，并检查覆盖缺口。
- 输出截断或不完整 JSON 应按既有协议纠正规则显式失败或恢复。协议恢复不代表事实、数学或语义已正确；不能把丢失内容后的较短响应自动记为质量成功。

## 五项 benchmark 的准备重点

### DeepSearchQA

优先消除通用提示中“只提供代表条目”对明确 `all`、完整列表或多条件集合查询的冲突。最终答案应清楚区分答案实体与背景解释，规范同一实体的别名，并保留公开题面要求的范围、日期和资格条件。必要时将检索或推理拆成条件覆盖、候选整理和资格复核；工具权限仍取决于冻结策略。

这里的完整性是公开任务要求，不由私有参考答案数量、`answer_type` 或参考内容反推。不修改 TP/FP/FN 或 F1 公式，不把缺失评分当真实零分，也不通过宽松匹配制造增益。

### WritingBench

优先使团队职责围绕所需成稿组织：内容构思与结构、语言与受众、连贯性与最终修订。研究型通用检查只在公开任务适用时使用；创意虚构不自动要求事实引用，非虚构中的具体事实与数字仍需支持。审稿聚焦实际职责和成稿缺陷，最终角色吸收有效修改并交付全文。

私有 checklist 保持 evaluator-only，不从 checklist 内容定制执行提示，不修改原生 1–10 量表或聚合方式。

### DeepResearch Bench II

准备通用报告能力：把公开问题拆成事实需求、分析问题、比较维度和决策输出；保留关键数值的时期、单位、分母及假设，给出支持结论的具体机制。证据与文本交接保留出处及其支持的主张，最终报告在任务语言下完成，不用泛泛概述替代深度。

这是纯 TEST 迁移目标，不能读取目标 rubric、blocked-source 名单或评分来改提示。真实运行仍需匹配各方法的冻结公开证据；本轮质量策略不替代证据准备，也不自动开放联网。

### 公开证据候选与长度限制

新证据准备策略在单次公开 query planner 后，固定最多 `4` 次 search 与 `8` 次 crawl，从不同查询的候选中均衡挑选抓取对象，避免候选槽位被单一查询的近似结果占满。检索、抓取、候选选择参数与策略版本记录在准备 identity；题面及公开来源是唯一输入，不使用参考答案、私有 rubric 或模型得分排序。旧 pack 保持可加载，不重写其内容或身份；新策略产生的新 pack 须重新冻结，并在正式比较中对各方法共享。

第二阶段 renderer 已实现并通过合成终验：当完整 pack 超出固定证据预算时，按公开题面/query 词项确定相关窗口，记录连续原文 `segments`、零基 Unicode 字符区间、每个来源的原文 SHA256，并按来源等额配额和剩余空间回填。英文词项与 CJK bigram 均纳入排序；旧 v1 pack 仍按旧 renderer 验证、可加载且不重写。检索上限仍固定为最多 `4` 次 search、`8` 次 crawl，renderer 不增加检索预算。

该策略改善窗口覆盖，但不保证完整语义：词项匹配无法覆盖所有同义词、隐式关系或未出现在题面/query 的相关表述；超长单句拆成 token 单元后，相关窗口的邻接范围仍可能漏掉远距离否定、数值或单位限定。不得把可见片段当作完整页面，或据此判断事实不存在。所有新 pack 必须冻结 renderer/candidate policy identity、原文 span/hash 和可重算 token 计数；未知 renderer 或 candidate policy 拒绝，不能静默按新规则读取。

### IFEval 与 IFBench

优先保证公开指令的机械约束和最终格式。内部规划、账本、协议 JSON 与最终用户正文严格区分：存储协议可以是 JSON，`answer` 中仍只包含公开任务要求的文本。只在公开任务允许的内容上改稿，不向最终正文泄漏内部 rubric IDs 或检查过程。

作者 checker 保持固定版本与哈希，评分时使用原始公开 prompt 和私有评测元数据。不能用 TEST checker 反馈反复修答案；本轮使用自行构造的合成公开任务验证格式执行，保持原生 strict/loose 指标。

通用 CLI 通过 `--benchmark ifeval` 或 `--benchmark ifbench` 选择任务，并要求显式传入 `--instruction-checker-source`：IFEval 使用固定 google-research 根目录，IFBench 使用固定 checkout 根目录。相应作者源码、已安装包和 NLTK 资源需事先准备；资源不齐时在模型构造前失败。评分前重新核对本地文件和依赖；checker 身份绑定 evaluator 版本与缓存，不能沿用其他 checker 的旧分数。此入口接线不等于独立 v5 全迁移驱动已完成。

## 追加质量优化（2026-10-04）：以原生指标检验收益

本次用户要求将工作重点从工程可运行转向六项 benchmark 的数值表现。以下是新增运行前改进，覆盖新实验中的通用 generator 和执行策略；已有封存 RR 身份与结果不变。此前的“未启动真实实验”状态仍适用于这些新增改进，不能把回归通过或上下文节省写成 benchmark 分数提高。

### 已实施的四项改进

1. **把多轮上下文留给新证据和修订。** 每轮只保留一份最新的完整 shared ledger，替换模型上下文中的旧运行时快照；不截断最新条目，不删除工具观察、peer 消息或模型响应。保留 `contributions[].ledger` 与顶层材料的既有结构，避免破坏当前消费者。旧模型输入仍保存在 trajectory 审计记录，最新贡献中的撤销与更正不会被历史账本重新引入。该变化作用于 `iterative_shared_ledger`，不增加调用或 token 上限。
2. **让写作审稿检查实际文字。** 规划与现有 Writer/Critic 技能要求交接预算内的真实段落、场景、对白或过渡，而非只交题纲与风格承诺。审稿指出可见片段、具体缺陷及其影响、可实施的修改；看不到稿件时只评价可见材料。Contributor 保留局部文字及审稿说明，终端角色整合为完整成稿，不为制造审稿增加角色或完整重复长稿。原有技能 ID、DAG 和执行规则保留。
3. **先构造受约束输出，再填充内容。** 通用公开质量提示增加可行性检查、固定起止文字和关键词预留、段落/行/句结构分配、明确计数范围及约束交互检查。修改时尽量只修必要片段，然后重新检查所有显式约束。计数语义来自公开任务，不假定各 benchmark 的 checker 相同；内部计数与推理不进入正文，模型自检不标为独立验证。新提示约增加 `290` 个 `cl100k_base` 输入 tokens/相关调用，计入原预算；真实 tokenizer 和费用以 provider usage 为准。
4. **避免经验容量被泛化建议占满。** 可用经验超过默认 `24` 条上限时，优先选择有公开任务信号支持、含不同实质匹配词和任务操作的条目，相关性相同时优先较新的条目。选中条目仍按原存储顺序交付。来源排除、时间边界、能力范围及否定操作检查仍先执行，私有 rubric、参考答案与分数不参与排序。小于容量的经验库保持原交付内容；这项主要服务更长进化轨迹或较大的合法来源状态。

### 六项指标的提分重点

| Benchmark | 优先改进的答案行为 | 判断实际收益的指标 |
|---|---|---|
| ResearchRubrics | 具体公开需求的覆盖、论证/计算、纠正实质审稿缺陷、有效终稿交付 | 原生带符号 rubric 分数；生成与完整评分覆盖率另报 |
| DeepSearchQA | 保留全部有支持的答案实体与资格条件，核对别名、去重及排除条件 | 原生每题 F1；precision/recall/fully-correct 分别诊断，不能仅靠多列猜测提高 recall |
| WritingBench | 有内容的成稿、实际段落审稿、语气/受众/连贯性、长度与重复控制 | 固定作者 checklist 的 1–10 分；不以更长输出代替更好写作 |
| DeepResearch Bench II | 事实/分析/比较/建议的覆盖与来源支撑，完整交接数值和限定条件 | 原生满足率与 blocked-source rate；只做预注册来源迁移 |
| IFEval | 从公开指令构造格式、检查词/句/段和关键词之间的交互 | 作者 prompt-level strict accuracy；保持原始答案文本和固定 checker |
| IFBench | 适应新约束组合，修改后复核已满足条件，避免额外包装文字 | 作者 prompt-level loose accuracy；辅助 strict 与 instruction-level 指标另报 |

数值提升必须在相同任务、公开输入、模型与注册预算下比较，并同时报告生成失败、评分缺失、实际 tokens/费用。成功子集均值与完整任务主指标分开，不能通过删除失败题提高成绩。按现行独立 v5，Initial 与 Selected 使用同一冻结执行策略，二者差异仍来自源内进化经验；单独评估本次 runtime 改进需要另行登记诊断身份，不能把旧 runtime 与新 Selected 的差值全归因于经验学习。

### Prompt 技巧的来源与使用边界

- [GEPA](https://arxiv.org/abs/2507.19457v2) 提供从轨迹与自然语言反馈诊断缺陷、提出并验证 prompt 更新的依据。本轮借鉴具体缺陷驱动的改进方式，没有加入其完整 Pareto 搜索器，也没有根据 TEST 选 prompt。
- [Self-Refine](https://arxiv.org/abs/2303.17651v2) 提供草稿、具体反馈、修订的依据。本轮在已有规划和执行预算内改进可见稿件及修稿交接；不据此额外循环或承诺其论文中的提升幅度。
- [ACE](https://arxiv.org/abs/2510.04618) 强调保留可复用细节、避免反复重写导致上下文信息丢失。本轮保留最新完整账本与审计历史，并按公开相关性使用已有经验；不复现完整 ACE 框架。
- [WritingBench 论文](https://arxiv.org/html/2503.05244v3) 讨论内容质量、材料融合、长输出与重复等挑战；[IFBench 官方说明](https://github.com/allenai/IFBench#how-to-run-the-evaluation) 明确其原生 loose 指标。本轮依据这些公开机制设计通用策略，没有读取目标 TEST 的题目、答案、checklist 或具体 checker 反馈来优化。
